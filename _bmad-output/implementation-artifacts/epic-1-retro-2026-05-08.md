## 4. Ce qui a fait mal

### 4.1 IPv6 regex masquait timestamps ISO 8601 (Story 1.9) — bug critique attrapé en runtime

**Le moment didactique de l'epic.** La regex initiale `(?:[0-9a-fA-F]{1,4}:){2,7}[0-9a-fA-F]{1,4}` (≥3 groupes hex) matchait `18:36:41` dans les timestamps ISO 8601 → tous les `"timestamp": "2026-05-05T[REDACTED_IP].659172Z"` masqués. Casserait `jq` parsing CI/Compliance.

**Invisible en unit tests, attrapé en runtime smoke test post-build** (`curl https://localhost:8443/ready`).

**Fix** : tightening `{3,7}` (require 4+ groupes hex) + alternation `::[0-9a-fA-F]{1,4}` pour collapsed forms. Test régression dédié `test_redact_pii_no_false_positive_on_iso_timestamps`.

**Lesson explicite documentée dans la story** :
> Les unit tests sur regex sont insuffisants — il faut systématiquement tester contre le format réel des logs structlog en runtime.

### 4.2 Bad-spec env var Caddy (Story 1.9)

Le draft AC1 prescrivait `CADDY_HOST_IS_TAILSCALE` boolean toggle directive-level conditionnel. Caddy ne supporte pas ce pattern. Pivot mid-implementation vers `CADDY_TLS_VALUE` (valeur tls littérale, env-templating idiomatique). **Pas attrapé en planif.**

### 4.3 Frottements shadcn CLI v4.6 (Story 1.8) — 3 issues

1. **ERESOLVE TS↔openapi-typescript** pré-existant — résolu par `frontend/.npmrc` `legacy-peer-deps=true`. Aurait dû être détecté en 1.1.
2. **shadcn CLI ne résout pas l'alias `@/...`** — fichiers créés littéralement dans `frontend/@/shared/components/ui/`. `mv` manuel via container.
3. **`sonner.tsx` self-import buggé + CSS vars sans préfixe `--color-`** — fix manuel post-CLI.

### 4.4 `eslint-plugin-boundaries` v6 deprecation silencieuse

Rule `boundaries/element-types` dépréciée → `boundaries/dependencies`. **Règle silencieuse sur certaines violations shared→feature.** Si non migré avant Epic 2, violations boundaries non détectées qui passeront en code-review-only.

### 4.5 `AuditEventRepo.record()` deferred → blocker latent Epic 2

## 5. Insights clés

1. **Smoke test runtime > unit test exhaustif.** Regex IPv6 1.9 prouve que pour tout pattern qui touche du runtime data (logs, headers, parsing), un curl/smoke contre le format réel attrape ce que pytest ne voit pas.
2. **Code-review-as-you-go > code-review-after-the-fact.** Story 1.3 = 8 must-fix accumulés. Stories 1.5+ = fix-batch dans la PR → meilleur ratio.
3. **Anti-scope explicit + deferred-pointer = velocity sustainable.** Quand Epic 2 démarre, on sait précisément ce qui n'est PAS fait dans la fondation.
4. **Multi-agent code review scoring (1.9) écarte les FP.** 5 Sonnet + 6 Haiku scoring 0-100 → 5/6 findings = FP éliminées au scoring ≤ 45, 1 réelle (90/100). Méthodologie reproductible Epic 2+.

## 13. Notes d'exécution C1 — Migration `eslint-plugin-boundaries` v6 (2026-05-08)

La migration "simple rename" `element-types` → `dependencies` ne suffisait pas. **3 changements requis** :

### 13.1 Renommer la rule + objet selectors (modern v6 syntax)

`frontend/eslint.config.js` :
```js
// AVANT (v5 silencieux à cause des deprecation warnings)
"boundaries/element-types": ["error", {
  rules: [
    { from: "feature", allow: ["shared", "styles"] },
    ...
  ]
}]

// APRÈS (v6 — object-based selectors)
"boundaries/dependencies": ["error", {
  rules: [
    {
      from: { type: "feature" },
      allow: [
        { to: { type: "shared" } },
        { to: { type: "styles" } },
      ],
    },
    ...
  ]
}]
```

### 13.2 Ajouter l'import resolver TypeScript (CAUSE DU SILENCE v5)

**Discovery majeur** : la règle ne fire pas — silencieuse même en v6 — sans `eslint-import-resolver-typescript`. Sans resolver, le plugin ne peut pas mapper `@/features/theme/ModeToggle` → `src/features/theme/ModeToggle.tsx` → element type `feature`.

```bash
npm install -D eslint-import-resolver-typescript
```

```js
// settings ajoutés
"import/resolver": {
  typescript: {
    alwaysTryTypes: true,
    project: "./tsconfig.json",
  },
}
```

### 13.3 Permettre les imports same-feature (barrel `index.ts`)

Une fois la règle active, le full lint a découvert 2 violations dans `src/features/theme/index.ts` (barrel reexportant `ThemeProvider` + `ModeToggle` de la même feature). Ce sont des imports légitimes.

Solution : capture group + Handlebars template pour matcher *même feature* :
```js
{
  from: { type: "feature" },
  allow: [
    {
      to: {
        type: "feature",
        captured: { feature: "{{ from.captured.feature }}" }, // same feature only
      },
    },
    { to: { type: "shared" } },
    { to: { type: "styles" } },
  ],
}
```

### 13.4 Validation smoke test

| Scénario | Attendu | Résultat |
|---|---|---|
| `shared/__test.tsx` import `@/features/theme/ModeToggle` | ❌ Error | ✅ Bloqué (`error: There is no rule allowing dependencies from "shared" to "feature/theme"`) |
| `features/__other__/test.tsx` import `@/features/theme/ModeToggle` | ❌ Error | ✅ Bloqué (cross-feature) |
| `features/theme/index.ts` barrel reexport `./ModeToggle` | ✅ Allowed | ✅ Passe (same feature) |
| Full `npm run lint` | ✅ 0 error 0 warning | ✅ Clean |
| Full `vitest` | ✅ 19/19 pass | ✅ 19/19 pass |

### 13.5 Lesson learned

Le rapport Story 1.8 mentionnait *« warnings de migration v6 rendent les violations silencieuses »* — la cause racine n'était pas seulement la deprecation warning, c'était l'**absence de resolver TypeScript**. Migrer la rule sans installer le resolver = on garde le silence avec un nom moderne. **Ajouter `eslint-import-resolver-typescript` est OBLIGATOIRE pour que `boundaries/dependencies` détecte quoi que ce soit avec des alias `@/...`.**

**À surveiller Epic 2+** : si quelqu'un ajoute un nouveau type d'élément (ex: `route` pour les routes TanStack Router), la règle doit explicitement le couvrir, sinon imports vers/depuis ce type seront silencieusement autorisés (`default: disallow` ne fire que si l'import résolvable matche un element type connu).
